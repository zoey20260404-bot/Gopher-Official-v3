# feat009：选岗报告 Workflow 与人工审批闭环

## 目标

把已确认用户档案、确定性岗位资格匹配和 LangGraph human-in-the-loop 串成可审计的选岗报告流程。系统先展示候选方案，用户审批后才生成最终报告。

## 用户流程

1. 用户创建报告，可提供考试、年份、地区和关键词过滤条件。
2. 系统基于权威档案调用 feat007 的确定性匹配能力，只选取 `eligible` 和 `uncertain` 岗位。
3. LangGraph 到达审批节点并通过 `interrupt` 暂停。
4. 用户查看候选岗位、资格状态、缺失档案字段和风险依据。
5. 用户可以批准候选集合中的部分岗位，或拒绝本次报告。
6. 批准后恢复 graph，由 LLM 基于已批准岗位和确定性依据生成 structured report；拒绝后流程终止。
7. 最终结果保存到 PostgreSQL，可通过报告详情接口读取。

## API

- `POST /api/v1/reports`：创建报告并运行至人工审批暂停点。
- `POST /api/v1/reports/{report_id}/decision`：批准或拒绝，并恢复 workflow。
- `GET /api/v1/reports/{report_id}`：读取本人报告状态和结果。

## 报告结构

本期采用：

- 优先考虑：确定性规则结果为 `eligible`；
- 需要复核：存在未知条件、备注或其他限制的 `uncertain` 岗位；
- 行动建议：围绕缺失字段和人工复核项给出下一步动作。

当前档案没有用户预估分数，因此不输出伪精确的“冲稳保”分档。

## 非目标

- 不修改 feat007 的资格规则。
- 不让 LLM 改写 `eligible/uncertain` 结论。
- 不生成或推测岗位分数、竞争比例和录取概率。
- 不支持审批候选集合之外的岗位。
- 不提供后台任务队列、批量报告、导出 PDF 或分享链接。
